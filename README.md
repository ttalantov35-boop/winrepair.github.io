# Сайт WinRepair Toolkit

Одностраничный сайт программы: русский и английский язык, единый синий фон, загрузка из GitHub Releases, комментарии через Giscus, форма обратной связи.

Все настройки находятся в одном файле — **`js/config.js`**.

## Структура

```
index.html        — страница сайта (русский текст)
404.html          — страница «не найдено»
css/style.css     — оформление
js/config.js      — НАСТРОЙКИ: GitHub, контакты, комментарии, форма
js/i18n.js        — английский перевод
js/main.js        — логика (язык, эффекты, релизы, форма)
img/              — логотип, иконка, картинка для соцсетей
robots.txt, sitemap.xml, .nojekyll
```

## 1. Укажите репозиторий и контакты

Откройте `js/config.js`:

```js
github: { owner: 'ваш-логин', repo: 'winrepair-toolkit' },
contacts: { author: 'Ваше имя', email: 'you@example.com', telegram: 'nick' },
```

Пока стоит `your-username`, кнопки GitHub и загрузки показывают подсказку вместо перехода.

## 2. Выложите программу в GitHub Releases

1. В репозитории программы: **Releases → Draft a new release**.
2. Тег, например `v1.0.0`, описание изменений (список через «-» — он попадёт в «Что нового»).
3. Прикрепите два файла: `winrepair-x64.exe` и `winrepair-x86.exe`.
4. **Publish release**.

Сайт сам подтянет версию, дату, размер, число скачиваний, SHA-256 и список изменений, а кнопки «Скачать» будут вести прямо на файлы. Разрядность Windows посетителя определяется автоматически, подходящая кнопка помечается «ваш ПК». Если в релизе только один `.exe`, он считается 64-битным, а кнопка 32-бит скрывается. Другие имена файлов настраиваются в разделе `assets` файла `config.js`.

## 3. Опубликуйте сайт на GitHub Pages

1. Создайте репозиторий (можно тот же, где программа, в папке `docs/`, или отдельный).
2. Загрузите содержимое этой папки.
3. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` или `/docs`.
4. Через минуту сайт будет по адресу `https://ваш-логин.github.io/имя-репозитория/`.
5. Замените `your-username.github.io/winrepair-toolkit` на свой адрес в `index.html` (теги `canonical`, `og:url`, `og:image`), `robots.txt` и `sitemap.xml`.

## 4. Подключите комментарии (Giscus)

1. В репозитории: **Settings → General → Features → Discussions** — включить.
2. Установите приложение Giscus: https://github.com/apps/giscus
3. Откройте https://giscus.app, введите репозиторий, выберите категорию (например *General*).
4. Скопируйте из готового кода `data-repo`, `data-repo-id`, `data-category`, `data-category-id` в раздел `giscus` файла `config.js`.

Комментарии автоматически переключают язык и тему вместе с сайтом.

## 5. Форма обратной связи

- **Без настройки**: если указан `email`, форма откроет почтовую программу посетителя с готовым письмом.
- **Formspree** (письма приходят на почту без участия посетителя): зарегистрируйтесь на https://formspree.io, создайте форму и впишите её адрес в `formEndpoint`, например `https://formspree.io/f/abcdwxyz`.

## Что стоит проверить и поправить

- Список возможностей, команды и системные требования написаны как типичные для такой утилиты — сверьте с тем, что реально умеет ваша программа (`index.html` и `js/i18n.js`).
- Демо на первом экране — анимация, а не реальный снимок программы.
- Скриншот программы — `img/screenshot.png`, он же на первом экране. Новый скриншот положите под тем же именем и поправьте `width`/`height` в `index.html`.

## Локальный просмотр

Просто откройте `index.html` в браузере. Загрузка релизов и комментарии работают и локально, если в `config.js` указан настоящий репозиторий.

## Резервные копии и откат

Перед крупными правками предыдущая версия сохраняется в папку `_backup/<дата>_vN`.
Чтобы вернуть её, скопируйте содержимое этой папки поверх файлов сайта.
Папку `_backup` не нужно загружать на GitHub Pages.
